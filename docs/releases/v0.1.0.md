# Glomancy Protocol v0.1.0

Status: **first public early-stage release**

Glomancy Protocol v0.1.0 is the first tagged public release of the transport-neutral protocol layer used to describe, validate, negotiate, and observe AI-originated work crossing into editor/tooling runtimes.

This release is intentionally small and auditable. It is not the commercial Glomancy product and does not include private model-provider integrations, credentials, billing, proprietary planning/orchestration, editor mutation implementations, desktop application code, installer/updater logic, or signing infrastructure.

## Why this release exists

The broader Glomancy product is being built as an AI-assisted editor copilot and automation layer. A natural-language request may eventually cause real changes inside a powerful editor or developer tool, so the boundary between "AI proposed this" and "a tool may execute this" should not be an unstructured text channel.

Glomancy Protocol provides a public contract for that boundary: versioned messages, compatibility negotiation, capability negotiation, approvals, task status, errors, evidence, tracing, bounded inputs, and conformance tooling.

For the broader product/protocol explanation, see `docs/GLOMANCY_OVERVIEW.md`.

## Included in v0.1.0

### Protocol core

- Rust protocol types and validation helpers under MIT.
- Wire protocol `0.4.0` compatibility behavior.
- Message contracts for:
  - handshake request/response;
  - task submit/progress/result/error/cancel;
  - approval request/decision;
  - evidence records;
  - heartbeat/liveness.
- Strict identifiers, timestamps, tracing metadata, error categories, risk levels, execution modes, task states, and public limits.

### Versioned schemas and registry

- Draft 2020-12 JSON Schemas for the public message surface.
- Versioned schema URNs.
- Canonical schema registry with SHA-256 digests.
- Repository validation that detects schema/hash, fixture-reference, and protocol-version drift.

### Capability negotiation profile v1

- Exact `name + version` matching.
- Unsupported required capabilities fail closed.
- Unsupported optional capabilities are omitted.
- Duplicate capability names are rejected by the public helper/profile.
- Task-time capability requests must be a subset of capabilities selected for the session.
- Capability negotiation does **not** grant authorization by itself.

### Conformance and integration tooling

- Public `scripts/glomancy_conformance.py` CLI.
- Payload validation by registered schema ID/message kind.
- Full valid/invalid fixture execution.
- Stable CI-oriented exit codes.
- Machine-readable capability conformance cases.
- Repository-local schema resolution without depending on the private Glomancy runtime.
- Executable transport-neutral `reference_consumer` example demonstrating wire compatibility, exact capability negotiation, task capability gating, schema resolution, fail-closed required-capability rejection, and the separate authorization boundary.
- Annotated `docs/REFERENCE_CONSUMER.md` guide for external implementers.

### Compatibility and evolution

- Machine-readable compatibility matrix and concrete cases.
- Conservative pre-1.0 behavior: patch differences within the same `0.x` minor line can be compatible; different pre-1.0 minor lines are treated as incompatible.
- Documented pre-1.0 deprecation/schema-evolution lifecycle.
- Explicit migration-note expectations for future breaking changes.

### Security and maintenance

- Fail-closed behavior for unknown message kinds, schema IDs, incompatible versions, and unsupported required capabilities.
- Public/private boundary CI checks for obvious credential/private-path/private-repository leakage.
- Supply-chain maintenance policy.
- Immutable SHA pinning for GitHub Actions used by CI.
- Dependabot monitoring for Cargo, Python conformance tooling, and GitHub Actions.
- Linux, Windows, and macOS test jobs.
- Formatting, Clippy, Rust tests, executable examples, Rustdoc, repository-contract checks, capability-profile checks, fixture validation, and conformance CLI smoke tests.

## Compatibility

The release contains:

- Rust crate version: `0.1.0`
- current wire protocol: `0.4.0`
- current public v1 schema line: `1.0.0` schema IDs

These version numbers are intentionally independent.

For wire protocol versions below 1.0, Glomancy Protocol uses conservative compatibility semantics:

- exact version -> exact compatibility;
- same major `0` + same minor + different patch -> patch compatible;
- different pre-1.0 minor -> incompatible;
- unknown message kind/schema -> reject.

See `docs/COMPATIBILITY.md` and `docs/DEPRECATION_POLICY.md` before implementing version negotiation.

## Security scope

Protocol validation is **not authorization**.

A payload passing schema validation, version negotiation, or capability negotiation does not mean an implementation should execute it. Authentication, authorization, policy, approval, sandboxing, editor permissions, and result validation remain responsibilities of the consuming implementation.

Security-sensitive reports should follow `SECURITY.md` rather than public issues.

## Public/private boundary

This release contains the open protocol contract only.

It deliberately excludes the commercial/private Glomancy implementation, including provider clients and credentials, BYOK/gateway logic, billing/cost controls, private agent/runtime internals, proprietary orchestration and planning, editor-specific mutation implementations, desktop application code, installer/signing/trust infrastructure, and internal reports/scripts.

## Current maturity

This is an **early-stage pre-1.0 release**.

It should not be interpreted as a claim of broad production adoption, industry-standard status, or long-term compatibility guarantees. The project already has executable conformance, a public reference consumer, and cross-platform CI, but real external integrations, independent implementations, contributor feedback, and production experience are still needed before stronger stability claims are appropriate.

## Getting started

```bash
cd glomancy-protocol
cargo test --all-targets
cargo run --example reference_consumer
python3 -m pip install -r requirements-conformance.txt
python3 scripts/glomancy_conformance.py fixtures
```
